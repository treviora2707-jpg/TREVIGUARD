## 2. Core Privacy Principles

### A. 100% Local On-Device Artificial Intelligence
- All machine learning inference, static Portable Executable (PE) feature extraction, Shannon entropy scoring, and YARA pattern evaluations are performed **locally on your host CPU and GPU** using the embedded ONNX Neural Runtime.
- **Zero Cloud File Transmission:** Your files, executable payloads, scripts, and documents are **never uploaded** to any cloud server, third-party API, or remote analytics cluster.

### B. No Collection of Personal Identifiable Information (PII)
- TreviGuard does **NOT** track, collect, log, sell, or transmit:
  - Your personal identity, name, or email address
  - Your web browsing history, cookies, or DNS requests
  - Keystrokes, passwords, credentials, or session tokens
  - Personal documents, photos, spreadsheets, or financial records
  - Network traffic contents or communications

### C. Strict Local Storage Architecture
- All operational data generated by the software resides exclusively in the user-designated directory (e.g., `D:\projects\antivirus\`):
  - **Local SQLite Database (`data/defender.db`):** Stores scan history, quarantined metadata, and local security events entirely offline.
  - **Encrypted Quarantine Vault (`data/quarantine/`):** Neutralized threats are encrypted locally using AES-GCM 256-bit cryptography with unique local session nonces.
  - **Diagnostic Logs (`data/logs/`):** Kept strictly on the local machine and never transmitted off-device.

### D. Hardware Telemetry & Sensor Isolation
- Real-time readouts for CPU clock/utilization, GPU VRAM/temperature, RAM capacity, and Battery status are gathered via native Windows Win32 APIs (`psutil`, `nvidia-smi`, `winreg`).
- These metrics are utilized **exclusively in volatile memory** to:
  1. Render the live Cyberpunk HUD dashboard widgets.
  2. Dynamically assign the optimal performance profile (High-Performance Workstation, Balanced, or Eco Mode).
- No hardware telemetry is ever compiled, profiled, or transmitted to any remote destination.

### E. Synthetic Decoy Canary Honeypots
- To defend against ransomware encryption outbreaks, TreviGuard generates lightweight, synthetic decoy canary files (e.g., `passwords_backup.xlsx`, `finance_2026.docx`) in an isolated honeypot directory (`data/canaries/`).
- These decoy files are purely synthetic mock data and contain zero genuine personal or organizational information.

## 3. Windows Permissions & Least Privilege Standard

During setup and execution, TreviGuard requests specific Windows authorizations strictly to perform its defensive duties:

| Permission / Authority | Technical Reason | Privacy Safeguard |
| :--- | :--- | :--- |
| **Administrator Privilege (UAC)** | Required to bind SafeGuard 3-Layer Firewall rules and flush process working sets via `EmptyWorkingSet`. | Confined strictly to defensive security actions; never modifies user personal files. |
| **Filesystem Watcher Observer** | Real-time monitoring of high-risk drop folders (Downloads, Temp, Canary decoys) for inbound malware. | Operates purely as an in-memory event listener; no document indexing or reading of private contents. |
| **Windows Startup Registry Key** | Optional persistence (`HKCU\...\Run`) to maintain continuous endpoint defense across system reboots. | Standard Windows autorun entry; completely removable at any time from Settings. |
